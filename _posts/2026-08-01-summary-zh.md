## [无状态 MCP 2.0 规范重燃热情，催生新工具](https://simonwillison.net/2026/Jul/31/stateless-mcp/#atom-everything) ⭐️ 8.0/10

Simon Willison 表示，MCP 2.0 规范（即 2026-07-28 Model Context Protocol 更新）引入了无状态设计，简化了 MCP 客户端和服务器的实现。他本周构建了三个新工具，包括 mcp-explorer 和 datasette-mcp，以展示新方法。 这是 MCP 自发布以来最重要的一次变更，使协议更易于实现，也更适合可扩展的 Web 应用。它还重新点燃了人们对 MCP 的兴趣，因为与让智能体完全访问 shell 相比，MCP 更安全、更易审计。 旧的有状态 MCP 需要两次 HTTP 请求：一次用于初始化会话并获取 Mcp-Session-Id，另一次用于调用工具。新的无状态 MCP 只需单个 HTTP 请求，通过 MCP-Protocol-Version 和 Mcp-Method 等头部信息，消除了服务器端会话状态。

## [硬停止规则：从 3 个 HCM 单体应用到 120 个领域微服务](https://www.infoq.cn/article/1GC0U88AkvaWbqO1DNlR?utm_source=rss&amp;utm_medium=article) ⭐️ 8.0/10

rss · InfoQ 中文 · 8月1日 10:00

**背景**: 单体应用将所有功能打包到一个可部署单元中，随时间推移可能变得难以维护和扩展。微服务架构将功能拆分为更小、可独立部署的服务，通常与业务领域对齐。“硬停止规则”是绞杀者模式（strangler fig pattern）的一种应用，即在日常开发过程中用新服务逐步替换遗留代码。HCM（人力资本管理）系统管理薪酬、福利、劳动力管理等 HR 职能。
